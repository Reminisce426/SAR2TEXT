- 主体任务：SAR 图像描述、自然语言生成 SAR；双向图文检索提供基线。研究重点是图像、语言和转换流程的规范化，以及事实理解、表达和空间定位。六周计划与 10-05、10-19、11-02 汇报节点见 [`docs/项目总计划_两周汇报制.md`](../../项目总计划_两周汇报制.md)。六阶段是职责分工，不是顺序等待的六个周期。
- 已有检索基线代码、配置协议和不依赖模型的最小测试；尚未得到正式 SAR 数据上的实验数值。描述与文生 SAR 模型仍是候选方案，不能把论文计划、代码存在、静态测试、真实推理或训练结果混为一谈。
- 阶段 1 的数据和模型首跑范围仍待用户审批。候选与限制见 [`今日任务与审批单.md`](今日任务与审批单.md)；不要据此自行下载数据/权重、挂载数据或启动微调。
- DBCloud 保存大数据、权重、缓存和训练中间产物；GitHub 保存代码、配置、环境清单、manifest、小型结果与研究报告。服务器与电脑尚未自动同步，未完成传输时不能称结果已回传。

## Mac 外出工作方案

在 Mac 的 Codex 桌面应用中，将 GitHub 仓库的本地克隆目录添加为 **一个 `SAR2text` 项目**。项目下保留一个持续使用的“总控/交接”任务，独立的代码修改、资料核查或阶段工作再各开任务；不要把所有阶段的长期工作挤进一个越来越长的对话，也不必为了还原 Windows 的八个本地任务而创建八个空任务。仓库文档和 Git 提交承载可复核上下文；Git 不同步 Codex 对话全文。

首次在 Mac 上操作：

1. 使用同一 GitHub 账号访问 [`Reminisce426/SAR2TEXT`](https://github.com/Reminisce426/SAR2TEXT)。确认仓库可见并已包含 Windows 推送的目标提交；若仍为空或无法访问，先不要按本说明假定同步完成。
2. 在终端执行 `git clone https://github.com/Reminisce426/SAR2TEXT.git`，进入克隆目录后运行 `git status --short` 和 `git log -1 --oneline`。私有仓库登录按 GitHub 自身提示完成；不要把访问令牌写入项目文件。
3. 在 Codex 桌面应用中打开该本地目录，保存为 `SAR2text` 项目。让第一项任务先读 `AGENTS.md`、本交接文档、六周计划和相关阶段文件，再核对当前 Git 提交与未提交改动。
4. 每次外出开始先 `git pull --ff-only`。需要改动时使用独立分支或 Codex 工作树，记录改动和验证结果，提交并推送到 GitHub；Windows 主任务审查后合并。返回 Windows 时先拉取并检查状态。遇到双方同时修改同一文件，先协调合并，不强制推送覆盖。
5. Mac 适合离线文档整理、代码实现、轻量测试和基于仓库证据的审查。实际 SAR 数据、GPU 推理和训练仍在 DBCloud 按获批方案运行，记录所用提交号、数据/模型版本、配置、命令、种子和指标。

## 对话与云端的关系

Windows 的八个本地任务属于原设备上的 Codex 任务，不会因 Git 推送出现在 Mac 项目中。本交接文档只汇总足够继续工作的决策和状态，不上传聊天全文。若以后使用 Codex Remote，在原 Windows 主机在线且连接设置完成时，可远程查看或继续原设备任务；这不是 Mac 本地项目的前提。Codex 云端任务可从已推送的仓库提交启动，但同样不会自动带入本地对话或 DBCloud 数据。相关核查见 [`Codex云端同步可行性.md`](Codex云端同步可行性.md)。
