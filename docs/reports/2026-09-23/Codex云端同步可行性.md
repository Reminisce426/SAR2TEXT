## 同步范围与限制

| 内容 | 判断与处理 |
| --- | --- |
| 代码、配置、Schema、计划、报告、轻量结果 | 适合纳入 Git，经提交和推送进入云端任务 |
| 原始 SAR 数据、权重、缓存、训练中间产物 | 按现有规则留在 DBCloud，仓库保存版本、清单、哈希与小型结果 |
| 本机主任务和六阶段任务的完整对话 | Git 推送不会携带对话。官方 Codex Remote 可让另一台已连接设备访问并继续当前主机的现有对话；这依赖原主机在线。也支持在匹配的 Git 项目之间将单个对话及 Git 状态交接到另一台已连接电脑，但不支持交接到 Codex 云端环境。云端任务需要用仓库内交接文档承接必要上下文 |
| 本机个人技能、插件和工具连接 | 不应假定随 Git 自动携带；需要在目标环境分别核查 |
| DBCloud 的 GPU、目录和运行进程 | 不会因代码接入而自动复制或挂载；本轮未验证云端直连 DBCloud，也未确认可用 GPU 规格 |

## 接入前需要处理的事项

1. 为 `AGENTS.md` 增加云端工作目录规则：本地继续使用既定主目录，云端使用实际 Git 根目录；禁止云端任务尝试访问 Windows 绝对路径。现有通讯录也不能假定在云端可用。保留主任务审查、最多两个阶段并行及数据/模型审批边界。
2. 将当前 `configs/openclip_vit_b32.json` 保留为 DBCloud 配置。该文件使用 `/remote-home/sh/...` 和 `cuda:0`；如需云端推理，另建经批准的样本配置，并验证数据、权重、设备及输出目录。
3. 云端首轮只运行现有最小测试，建议固定 Python 3.11。先检查测试所需导入，配置轻量 setup，避免首轮自动安装全部 PyTorch/OpenCLIP 依赖。正式模型环境应另行安装并验证完整依赖。
4. 首次上传前审查文件与提交历史中的凭据、数据许可及未合并工作树成果；私有仓库也需要明确上传范围。

云端允许配置运行时版本、setup 脚本及环境变量；任务执行阶段默认关闭联网，setup 阶段可联网安装依赖。容器缓存不是成果备份，需把应保留的成果提交回仓库。[官方环境说明](https://learn.chatgpt.com/docs/environments/cloud-environment)。

跨设备查看本地八个任务：在原 Windows 主机的 ChatGPT 桌面应用启用 `Settings > Connections > Control this PC`，用同一 ChatGPT 账号与工作区在手机 Remote 中连接；支持远程控制的另一台 Mac/Windows 桌面应用可用 `Control other devices` 连接。原主机需要保持开机、联网且应用运行。若要让任务实际在另一台电脑执行，先在目标电脑保存同一 Git 仓库项目，再逐个使用 Handoff；这不是 Codex 云端容器的功能。[官方远程连接说明](https://learn.chatgpt.com/docs/remote-connections)。本轮已定位当前任务、主任务及六阶段任务的本地主机记录，但未实测第二台设备连接或逐个交接。

不用 Remote 时，对话只能以内容副本跨设备使用：可将重要决策整理成 Markdown 交接文档并经审核纳入私有仓库，Mac 上据此新建任务；如客户端支持，也可创建只读对话快照链接。官方明确 macOS 桌面应用支持快照；快照不会随原对话更新，不能从快照继续原任务。个人账号的分享链接可被任何持有链接的人打开，分享前需审查内容。本轮未创建任何分享链接，也未导出对话全文。[官方快照说明](https://learn.chatgpt.com/docs/use-chatgpt)。

## 建议执行顺序与验收

1. 确定 GitHub 仓库所属账号和私有仓库名称，完成上述最小适配与上传范围核查。
2. 创建或选用私有远程仓库，配置 `origin`，推送审核后的主分支。
3. 在 Codex 云端授权该仓库，创建环境；用户账号的实际云端入口及仓库授权状态尚未核验。
4. 首个云端任务只读取研究计划和 `AGENTS.md`，记录实际提交 SHA，运行 5 项最小测试；不下载数据、权重或执行训练。
5. 通过一个小型文档修改验证云端差异/PR、主任务审查合并、本地拉取的闭环。
6. 后续按“本地提交并推送 → 云端从指定分支工作 → PR 审查合并 → 本地拉取”协作。DBCloud 另行拉取代码并回传小型结果；当前没有自动同步机制。

验收须同时满足：云端能检出正确提交、测试通过、差异能回到远程仓库并在本地拉取。完成这些步骤后才能称为“已接入并验证同步”；本轮仅确认技术路线可行。
