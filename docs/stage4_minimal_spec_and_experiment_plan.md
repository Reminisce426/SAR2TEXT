# 阶段 4：最小规范草案与实验计划

版本：`v0.1-draft`  
状态：待阶段 2/3 输入后冻结并执行  
研究对象：Sentinel-1 GRD 图像—自然语言语义对齐  
当前主验证任务：冻结 OpenCLIP ViT-B/32 的零样本双向图文检索（不把图像描述或文字生成 SAR 的结论混入本阶段）

## 1. 本阶段要回答的问题

本阶段只回答一个可检验问题：在同一数据、同一划分、同一冻结模型和同一推理预算下，对图像、文本和处理流程进行显式规范化，是否能提高零样本图文检索的准确性、稳定性和可复现性？若以后进入微调实验，再另行要求同一训练预算。

本阶段不把 OpenCLIP、SAR-CLIP 或 SAR-TEXT 当作创新；它们只可作为冻结或微调基线。规范化也不预设有效，最终结论必须由消融实验和置信区间支持。

核心比较采用 2×2 因子设计：

| 组别 | 图像输入 | 文本输入 | 目的 |
|---|---|---|---|
| A | `I0` 阶段 3 冻结的原始基线输入 | `T0` 原始文本 | 基线 |
| B | `I1` 规范图像 | `T0` 原始文本 | 图像规范化的增益 |
| C | `I0` 原始基线输入 | `T1` 规范文本 | 语言规范化的增益 |
| D | `I1` 规范图像 | `T1` 规范文本 | 联合规范化及交互效应 |

这里的“原图”不是未经处理的 Sentinel-1 DN，而是阶段 3 已冻结且可复算的模型输入 `I0`。A/B 只能改变本阶段声明的图像规范变量，其余处理必须一致。

阶段 2/3 到位后，先填写下表并冻结为 `stage4-input-v1`；未填写前不得启动正式实验。

| 输入 | 必填内容 | 当前状态 |
|---|---|---|
| 数据集 | 名称、版本、许可、样本数、地点/时间范围、文本来源 | 待阶段 2 |
| SAR 产品 | product ID、模式、产品级别、分辨率、极化、轨道方向、处理基线 | 待阶段 2 |
| 划分 | train/val/test 清单及哈希；同源切片分组规则 | 待阶段 2 |
| 基线图像 `I0` | 波段、物理量、数值域、裁剪、缩放、通道映射、尺寸 | 待阶段 3 |
| 基线文本 `T0` | 原文清理规则、语言、每图文本数 | 待阶段 3 |

## 3. 图像最小规范 `I1`

### 3.1 必须保存的元数据

每个样本至少保存：

- 唯一 `sample_id`、源文件路径和 SHA-256；
- Sentinel-1 product/granule ID、获取时间、空间范围或中心点；
- 成像模式、产品级别、像素间距/目标分辨率；
- 可用极化（如 VV/VH），不得把缺失极化填成真实观测；
- 轨道方向、相对轨道号（可得时）、处理软件及版本；
- 辐射量（DN、beta0、sigma0 或 gamma0）、线性/分贝域；
- 热噪声去除、边界噪声处理、几何/地形校正、重采样及斑点滤波状态；
- NoData/阴影/叠掩等掩膜的来源与含义。

原因是 Sentinel-1 Level-1 产品提供校准 LUT，可生成 beta0、sigma0、gamma0；这些量不能只写成模糊的“灰度”。Copernicus Data Space 的 S1 GRD 接口也明确区分后向散射系数、正射校正、辐射地形校正和斑点滤波选项。

### 3.2 数值栅格路径（首选）

`I1` 的最小候选流程如下；最终参数只能由训练集拟合，随后冻结用于验证集和测试集。

1. **输入一致性检查**：只在相同产品类型、模式和约定物理量内比较；不同极化组合分层处理。
2. **无效值先于对数处理**：读取产品 `dataMask` 或可靠 NoData 掩膜；将 NaN、Inf、非正线性功率及明确边界噪声标为无效。不得先以 0 填充再取对数。
3. **物理量冻结**：默认候选为校准后的 `sigma0` 线性功率；若阶段 2 已统一采用 `gamma0` 或做辐射地形校正，则沿用该量，不能在 A/B 间切换。
4. **dB 转换**：仅对有效正值计算 `x_db = 10 log10(max(x_linear, eps))`；`eps` 只用于数值安全，不将无效像元伪装为有效低散射。
5. **裁剪**：每个极化在训练集有效像元上估计全局分位点 `[q_low, q_high]`，首选候选为 `[1%, 99%]`；不得逐图估计分位点。冻结实际阈值并记录训练清单哈希。
6. **缩放**：将冻结裁剪区间线性映射到 `[0,1]`。若模型要求 ImageNet/OpenAI CLIP 均值方差，作为模型适配的最后一步单独记录。
7. **通道映射**：双极化 VV/VH 的主候选为 `[VV_db, VH_db, VV_db - VH_db]`。差值通道使用训练集全局阈值独立裁剪。单极化样本不得伪造 VH；应单独分层，或显式三通道复制并标记 `channel_policy=replicate_single_pol`。
8. **空间处理**：重投影、重采样、裁块和 resize 的顺序、算法、输出尺寸固定。标签/掩膜使用最近邻；连续后向散射值使用阶段 2/3 冻结的插值方法。
9. **掩膜传播**：resize 前后保留有效像元掩膜；记录 `valid_fraction`。低于冻结阈值的样本剔除或分层报告，不能在看过测试性能后调整阈值。
10. **显示图分离**：用于论文展示的直方图拉伸、伪彩色、锐化和注记不得回流为模型数值输入。

注意：是否做热噪声去除、斑点滤波或辐射地形校正属于上游产品处理选择，不应在本轮“仅归一化”对照里同时变化。若确需研究，应另设单因素扩展实验。

### 3.3 显示图路径（降级方案）

对无法恢复物理量的 PNG/JPEG：

- 固定颜色空间解码、alpha 处理、尺寸、插值和像素范围；
- 去除边框、比例尺、文字注记只允许依据预先定义的版式规则；
- 不做逐图自动对比度拉伸；
- 保存原文件哈希与转换后数组哈希；
- 结果必须写成“显示图输入上的规范化效果”，不得外推为物理 SAR 数值规范的效果。

## 4. 语言最小规范 `T1`

### 4.1 原则

- **忠实**：只表达标注、元数据或可审计人工判读支持的事实。
- **原子化**：一句只承载少量可核验事实，避免文学化推断。
- **可比**：同一概念使用稳定词项、量纲、覆盖度区间和关系表达。
- **保留不确定性**：不把“疑似”“可能”强行改写成确定事实。
- **证据可追溯**：文本中每个事实单元都能指向证据来源。

### 4.2 结构化中间表示

规范文本先生成结构化记录，再由固定模板渲染；字段定义见 `schemas/sample_record.schema.json`。

| 字段 | 约束 |
|---|---|
| `primary_feature` | 1 个主要地物类别；来自版本化受控词表 |
| `secondary_features` | 0–3 个次要地物，按显著度排序 |
| `coverage` | 覆盖度区间：`trace([0,10%))`、`minor([10%,30%))`、`substantial([30%,60%))`、`dominant([60%,100%])`、`unknown` |
| `spatial_relations` | 受控关系，如位于中心/边缘、相邻、包围、穿过、平行；必须有两个实体 |
| `uncertainty` | `confirmed/probable/possible/unknown`，来源必须可解释 |
| `evidence` | `dataset_label`、`metadata`、`human_annotation`；禁止把待测模型输出当金标准 |
| `prohibited_inference` | 天气、材质、用途、灾害原因等无证据推断的审计标记 |

首版词表不追求“大而全”。由阶段 2 数据标签起步，合并同义词但保留 `original_term`，每个规范词项包含定义、包含项、排除项、版本号。中文词项和英文词项需一一映射，不能依赖临时机器翻译。

### 4.3 渲染模板

最小模板：

> 图像主要包含{主要地物}（{覆盖度}），并可见{次要地物}；{空间关系}。该描述的判定置信度为{不确定性}。

缺失字段整句省略，不输出“无/未知”堆砌。示例仅演示格式，不代表真实样本：

> 图像主要包含水体（占主导），并可见建成区；建成区沿水体边缘分布。该描述的判定置信度为较高。

否定事实默认不写入普通 `T1`。否定句仅在证据能支持缺失时使用，并单独进入否定测试集；“未观察到”不能等同于“绝对不存在”。

### 4.4 文本规范化操作日志

每条 `T0 -> T1` 保存：

- 原文、规范文、词表版本和模板版本；
- 拆分后的原子事实；
- 每项事实的证据类型和证据定位；
- 执行的操作：同义词归一、歧义消解、覆盖度离散化、关系标准化、不确定性保留、删除无证据事实；
- 自动处理器版本、人工复核者匿名 ID、复核时间。

禁止用测试集检索结果反向修改具体文本；规范规则只在训练/验证阶段制定并冻结。

## 5. 流程规范

### 5.1 防泄漏划分

不能把同一原始产品的相邻切片随机分到 train/test。优先按 `source_product_id` 分组；若研究目标需要空间泛化，再按地理单元分组；若需要时间泛化，再按获取时间分组。划分策略由阶段 2 预注册。

所有分位点、均值方差、词表映射、模板选择和阈值只能用训练集拟合；验证集用于模型选择；测试集只在方案冻结后评估。

### 5.2 可复现记录

每次运行至少记录：

- Git commit、环境锁定文件、CUDA/PyTorch/OpenCLIP 版本；
- 数据清单及文件哈希、划分哈希、规范配置哈希；
- 模型名、权重文件 SHA-256、精度模式；
- 随机种子、每卡 batch、梯度累积、有效 batch、优化器、学习率、训练步数；
- GPU 型号/数量、运行时长、峰值显存；
- 每个 epoch 的损失和验证指标、最终预测明细，而不只保存汇总表。

当前零样本四组必须使用相同的数据样本、划分、候选库、OpenCLIP 模型与同一权重哈希，并保持相同推理精度和 batch 设置。若未来另做微调版四组，还必须固定初始化、优化器、学习率、训练步数和有效 batch；因 OOM 调整每卡 batch 时，只能通过梯度累积维持相同有效 batch，并记录差异。

### 5.4 与阶段 3 基线的衔接

当前阶段 3 配置 `configs/openclip_vit_b32.json` 使用 `ViT-B-32`、本地 `ViT-B-32.pt`、`fp32` 和固定测试清单；图像由 Pillow 读取并转成 RGB。因此：

- `I0` 就是阶段 3 的 RGB 读取与官方 OpenCLIP 预处理，不能在本阶段暗改；
- `I1` 应先离线生成规范图像缓存，再用同一读取/推理代码加载，或给阶段 3 增加可审计的数值栅格适配器；
- A/C 指向相同的 `I0` 图像，B/D 指向相同的 `I1` 图像；四份清单保持 `image_id`、`caption_id`、split 与行级对应关系不变；
- T0/T1 的变更必须同时作用于相应的 text-to-image 查询和 image-to-text 候选文本；
- 若只有 test 清单，不能从 test 拟合裁剪分位点或词表决策，必须由阶段 2 提供独立 train/calibration 部分，或在实验前登记完全固定且不由本数据估计的物理阈值。

### 5.3 工件命名

建议运行 ID：

`s4-{A|B|C|D}-seed{n}-{data_hash8}-{config_hash8}`

每个运行目录应包含 `config.yaml`、`environment.txt`、`metrics.json`、`predictions.parquet`、`stdout.log` 和模型权重或权重引用哈希。

## 6. 主实验：2×2 配对因子设计

### 6.1 执行顺序

1. 用阶段 3 完全复现 A，误差在预先允许范围内后再继续。
2. 在训练集或独立 calibration 集拟合并冻结 `I1` 参数及 `T1` 词表/模板。
3. 生成 B/C/D 的输入缓存和哈希，核验四组样本 ID 完全一致。
4. 使用同一冻结权重运行 A/B/C/D；零样本推理没有训练随机性，不用“多种子平均”制造稳定性证据。
5. 同配置至少重复推理 2 次检查可复算性；若硬件/算子无法做到逐值相同，报告最大分数差和排名变化。
6. 所有规则在验证集冻结后，再一次性评估测试集。
7. 保存逐查询排名/分数，用配对统计而非只比较汇总均值。

### 6.2 指标

主任务是图文检索，必须双向报告：

- text-to-image：R@1、R@5、R@10；
- image-to-text：R@1、R@5、R@10；
- 双向 mean Recall（主汇总指标）；
- 有多相关项时增加 mAP 或 nDCG，并明确 relevance 定义；
- 稳定性：同义改写、否定最小对和输入格式变化下的排名/得分变化；
- 可复现性：相同零样本配置重跑差值、失败率、运行配置/数据哈希完整率。

若未来开展微调实验，才增加不少于 3 个预先固定种子的均值、标准差和极差；零样本与微调结果不得合并统计。

样本级配对 bootstrap（按 query 分组，建议 10,000 次）给出 95% 置信区间。主结论同时报告效应量和区间，不以单个最好种子下结论。

### 6.3 因子效应

设四组主指标分别为 `M_A, M_B, M_C, M_D`：

- 图像规范化平均效应：`E_I = ((M_B-M_A) + (M_D-M_C))/2`
- 文本规范化平均效应：`E_T = ((M_C-M_A) + (M_D-M_B))/2`
- 交互效应：`E_IT = M_D-M_C-M_B+M_A`

同时保留最直观的三项配对差值：`B-A`、`C-A`、`D-A`。若交互效应显著，不能把 D 的全部提升分别重复归功于图像和文本。

### 6.4 决策规则（执行前冻结阈值）

阶段 2/3 到位后，应结合 A 的波动和数据规模填写最小实际意义差异 `delta`。建议判定框架：

- **有效**：主指标配对差值的 95% CI 下界大于 0，且点估计达到 `delta`；
- **可能有效**：区间跨 0，但点估计达到 `delta`，需要更多种子/样本；
- **无充分证据**：区间跨 0 且点估计未达到 `delta`；
- **有害**：95% CI 上界小于 0，或明显损害否定敏感性/事实支持度。

不得在看到测试集后改变 `delta`、主指标或样本排除规则。

## 7. 三类专项测试

这些测试与 A–D 主测试使用同一冻结模型，但作为独立测试套件报告；不把其文本加入主训练集。

### 7.1 同义改写不变性

为测试集中每条合格查询制作 2–3 条保持事实、实体、关系、覆盖度和不确定性不变的改写。改写不得新增或删减事实。

指标：

- 原句与改写的 R@K 差值；
- 同一图像排名变化的绝对值中位数；
- 原句/改写 Top-K 结果集合的 Jaccard；
- 文本嵌入余弦相似度（诊断指标，不代替检索指标）。

期望：规范化模型对等义表达更稳定，但不能通过把所有文本压成同一模板而牺牲区分性。故同时检查不同事实文本的嵌入分离度。

### 7.2 否定和最小反事实敏感性

从有可靠标签的事实生成最小对：只改变一个事实，如“包含水体”与“不包含水体”、或把一个支持类别替换为不支持类别。人工复核反事实确实与图像矛盾或不受支持。

指标：

- 成对准确率：`s(image, positive) > s(image, negative)` 的比例；
- 负样本裕量：`s_pos - s_neg` 的均值、中位数和 95% CI；
- 否定文本误入 Top-K 的比例；
- 分事实类型（类别、关系、覆盖度）报告。

若模型对正句和否定句得分几乎相同，即使普通 R@K 上升，也不能宣称“语义对齐更准确”。

### 7.3 事实支持度

建立经人工核验的小型审计集，每条文本拆成原子事实，并标为 `supported`、`contradicted` 或 `unknown`；`unknown` 不强行并入负类。

检索阶段使用两类评估：

- 支持文本应高于只含一个错误事实的最小反事实：报告 pairwise accuracy/AUC；
- 按受支持事实数分层，观察分数是否随事实支持度单调变化（Spearman 相关仅作诊断）。

如果后续扩展到图像描述任务，再增加原子事实 precision、recall、F1 与 hallucination rate；不能直接用检索结果替代生成式评价。

审计集建议先做 200 对左右的开发版，并对不少于 20% 做双人复核；正式规模由阶段 2 的类别数和数据量决定。报告一致性（Cohen's kappa 或 Krippendorff's alpha）以及分歧裁决规则。

## 8. 扩展但非主结论的实验

- **跨格式 4×4 测试**：分别用 A/B/C/D 训练的模型，在四种输入组合上评估，测量部署时遇到未规范输入的鲁棒性。它不能替代主 2×2 匹配实验。
- **图像规范单因素消融**：依次测试无效值策略、dB、全局裁剪、通道映射；一次只改变一项。
- **语言规范单因素消融**：词表、覆盖度、关系、不确定性、证据过滤逐项加入。
- **冻结编码器 vs 微调**：本阶段以冻结零样本为主；若资源允许，再进行同预算微调，至少 3 个预先固定种子，并与零样本分表报告。

## 9. 质量门槛与停止条件

进入正式实验前全部满足：

- [ ] A 可按阶段 3 配置复现，且指标误差在预设范围内；
- [ ] 四组样本 ID、划分和有效样本数核验一致；
- [ ] 所有规范参数仅由训练集拟合；
- [ ] `I0/I1/T0/T1` 各抽查至少 50 条，无明显错配；
- [ ] 图像数值统计无 NaN/Inf，掩膜比例有日志；
- [ ] `T1` 每个原子事实都有证据定位；
- [ ] 测试集未参与词表、模板、阈值或超参数选择；
- [ ] 运行配置、环境、权重、数据和输出都有哈希或版本号。

出现以下任一情况应暂停：样本错配、训练/测试同源切片泄漏、物理量无法辨认、A 无法复现、四组预算不一致、规范文本引入无证据事实。

## 10. 阶段 2/3 到位后的最短执行清单

1. 填写第 2 节输入契约，确认本阶段只做检索。
2. 从 100–500 个训练样本生成 `I1/T1` 预览并人工抽查。
3. 用小规模子集跑 A/B/C/D 单种子冒烟测试，验证管线而不报告科研结论。
4. 修订并冻结规范、主指标、`delta` 与排除规则；若增加微调实验，再冻结种子列表。
5. 执行完整多种子实验和三类专项测试。
6. 生成逐查询结果、配对置信区间、失败案例和数据谱系报告。
7. 依据预注册规则判断保留、修改或否定规范候选。

## 11. 当前未解决的问题

1. 正式数据是物理数值栅格还是已渲染图像？是否同时有 VV/VH？
2. 上游采用 sigma0 还是 gamma0，是否已做热噪声去除、边界噪声处理与地形校正？
3. 文本来自人工描述、地类标签、模板生成还是公开数据集？
4. 一图多文/一文多图如何定义相关性？这决定 R@K、mAP/nDCG 的标注方式。
5. 阶段 3 是零样本 OpenCLIP、线性探针还是端到端微调？
6. 地点、产品、相邻切片或时间上的泄漏风险如何控制？
7. 主线最终是否只保留图文检索，或另立图像描述/文字生成 SAR 子任务？后三者须单独定义模型与指标。
