# 结论证据验收表

结论验收对象是“可写入报告、摘要、答辩或 Demo 的一句主张”。每条结论分配 `claim_id`，并在 [`../../templates/conclusion_evidence.csv`](../../templates/conclusion_evidence.csv) 中追踪。

## 通用门槛

一条结论只有同时满足以下条件才标为“通过”：

- 结论对象、比较对象、适用数据和指标定义明确；
- 数据、代码、模型和配置版本可定位；
- 结果由记录文件支持，且可追溯到原始输出；
- 对照遵循同模型、同数据、同划分、同评价、同预算原则；无法完全相同时已披露差异；
- 已检查明显的数据泄漏、重复样本和评测脚本错误；
- 表述强度不超过证据强度，并写明限制与不适用范围；
- 至少一名非原运行者复核关键证据。

## 按结论类型的最低证据

| 结论类型 | 最低证据 | 建议判定标准 | 常见不通过原因 |
|---|---|---|---|
| 基线可复现 | 固定版本、完整配置、环境、日志、指标；独立复跑 | 复跑差异在预先定义容差内 | 只记录最好结果；缺随机种子或划分 |
| 规范提升准确性 | 无规范/有规范对照；同条件；主指标与置信区间或重复运行 | 达到预设效应阈值，方向稳定 | 同时改变数据或模型；只看单样例 |
| 规范提升稳定性 | 多随机种子、扰动或跨子集结果；波动统计 | 预定义稳定性指标改善 | 仅凭平均值推断稳定 |
| 规范提升可复现性 | 独立环境或独立成员复算；步骤和产物核对 | 按文档成功生成目标产物且误差达标 | 原作者本机重复运行即称可复现 |
| 模型改进有效 | 同预算强基线、重复运行、消融和误差分析 | 主指标达到预设阈值，关键消融支持机制 | 参数量/训练时长不同；缺消融 |
| 泛化能力 | 跨区域、时间、传感器条件或任务分布的独立评测 | 多个预定义域上表现一致或边界明确 | 仅同分布测试却称泛化 |
| Demo 能力 | 可重复输入、冻结模型、来源可查的输出 | 演示与离线结果一致，失败样例披露 | 手选样例、手改输出、不可追踪 |

“建议判定标准”必须在看正式测试结果前量化；若事后修改，要记录原因并降级为探索性分析。

## 验收结论状态

| 状态 | 含义 | 可用于何处 |
|---|---|---|
| 草拟 | 仅形成待检验表述 | 研究计划 |
| 证据不足 | 已有部分证据但未达门槛 | 讨论或待办，不进摘要 |
| 待复核 | 材料齐全，尚未独立复核 | 内部汇报 |
| 通过 | 满足通用门槛及类型门槛 | 报告正文、摘要、答辩、Demo |
| 否决 | 证据反驳或设计无法支持 | 负结果/限制，不能按原表述使用 |

## 最终逐条复核问题

1. 去掉形容词后，结论是否仍清楚说明“什么相对什么，在何处，以何指标发生何变化”？
2. 是否存在更弱但更准确的表述？
3. 结论是否把相关性写成因果性？
4. 结论是否把工程实现、第三方基线或实验支持误称为原创模型贡献？
5. 读者能否从 `claim_id` 找到 `run_id`、配置、日志、原始结果和复核人？
