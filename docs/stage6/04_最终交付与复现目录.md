# 最终 Demo、报告、代码包与复现目录设计

## 最终 Demo

Demo 的目标是展示被验收的研究能力，不预设最终一定包含全部双向任务。

### 最小页面/流程

1. **任务选择**：图文检索；若后续正式纳入，再增加 SAR 图像描述或文字生成 SAR。
2. **输入与规范化预览**：显示原始输入、规范化后输入、规范版本和规则触发记录。
3. **基线与方法并列输出**：同一输入下并列展示，不隐藏失败样例。
4. **证据面板**：模型/数据/配置版本、关键指标定义和结果记录 ID。
5. **限制说明**：适用范围、已知失败模式、非能力范围和许可限制。

Demo 展示值必须来自已冻结结果文件或可重复推理，禁止手工改写分数。若使用示例集，需记录样本 ID 与选择规则，避免只挑成功案例。

## 最终报告

建议结构：

1. 研究边界与术语定义；
2. 数据、规范对象和许可状态；
3. 评价协议与公平比较条件；
4. 可复现基线；
5. 规范提案及版本；
6. 对照实验、消融、稳定性与误差分析；
7. 如有：模型适配或改进；
8. 贡献分类与第三方边界；
9. 限制、伦理和可复现性说明；
10. 结论证据索引。

每张结果表需标注数据版本、划分、指标实现、运行次数或随机种子、统计口径和对应 `run_id`。

## 代码包

代码包应至少包含：

- 环境锁定文件与软硬件说明；
- 数据获取/校验说明，不擅自再分发受限资产；
- 数据预处理与规范化脚本；
- 基线训练/推理/评价入口；
- 本项目方法的独立入口；
- 配置文件、测试和最小样例；
- 第三方声明、引用文件和变更说明；
- 从零复现的命令顺序和预期产物清单。

## 最终打包验收

- [ ] 在干净环境中按 README 完成最小复现。
- [ ] 数据哈希、划分清单和配置哈希可追踪。
- [ ] 表格/图能够由脚本从原始结果重建。
- [ ] Demo 示例能关联到样本、模型和运行记录。
- [ ] 报告中的数字与结果文件自动或人工双重核对。
- [ ] 不含密钥、个人信息、缓存、大型受限数据或无许可权重。
- [ ] 第三方资产、项目贡献和实验支持三者界限清楚。
