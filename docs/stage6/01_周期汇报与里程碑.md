# 周期汇报与里程碑管理

## 汇报节奏

- 建议每 1–2 周汇报一次；遇到任务边界变化、数据许可风险或无法复现时，不等待固定周期，立即汇报。
- 每次汇报只陈述本周期已经发生且有证据可查的内容。
- 计划、假设和结果分栏记录，不用“预计有效”替代实验结论。

## 状态定义

| 状态 | 含义 | 可接受证据 |
|---|---|---|
| 未开始 | 尚未执行 | 无 |
| 进行中 | 已执行但未达到验收条件 | 运行日志、草稿、局部输出 |
| 待验证 | 有初步结果，但尚未完成复算、对照或核查 | 初步结果文件与待办项 |
| 已验证 | 达到该任务预先定义的验收标准 | 配置、日志、结果、复核记录 |
| 阻塞 | 因数据、算力、权限或定义不清无法继续 | 阻塞原因与解除条件 |
| 放弃 | 经记录后不再继续 | 决策依据、影响范围、替代方案 |

## 每次汇报必须回答

1. 本周期目标是否完成，证据在哪里？
2. 使用的数据、模型、代码和配置版本是否冻结？
3. 有无改变公平比较条件，例如数据划分、训练预算或评价脚本？
4. 新增了哪些事实、假设和建议？三者是否分开？
5. 哪些结论仍不能写入论文？缺少什么证据？
6. 是否影响主线任务：检索基线、SAR 图像描述或文字生成 SAR？

具体填写使用 [`../../templates/weekly_report.md`](../../templates/weekly_report.md)。

## 阶段回传主流程格式

```text
阶段：
本阶段确定的结论：
已完成成果及文件位置：
验证结果：
仍未解决的问题：
是否需要修改研究主线：
建议下一步：
```

其中“本阶段确定的结论”只允许填写已通过证据验收的结论；模板完成、目录建立等属于过程成果，不等同于模型或方法结论。
